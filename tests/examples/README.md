# Example layouts

All twenty `.tosc` files here ship with TouchOSC itself, under **Help >
Examples** in the editor. They are the corpus the tests check against: read,
round-tripped byte-for-byte, and mined for what the application actually
writes.

That provenance is what makes them useful beyond coverage. When a question is
about what is *idiomatic* rather than what is *possible* -- how a `PAGER`
insets its pages, whether a page needs a `tabLabel`, how large text should be
relative to its box -- these files are the only evidence available short of
opening TouchOSC and checking. Several of the library's validation rules exist
because a proposed rule fired on a file in here and turned out to be wrong.

## Not in here

`tests/data/` is a different collection -- fixtures inherited from
[tosclib](https://github.com/AlbertoV5/tosclib), layouts written to exercise
one corner of the format, and a few generated by py2tosc itself. Nothing in
there is evidence about what TouchOSC considers normal, and the eight files at
640x860 are tosclib's fixture size rather than a design decision.

Minimal files hand-drawn in the editor to settle a single question have earned
their keep twice now -- once for how a `GRID` tiles its cells, once for how a
`PAGER` insets its pages. They beat large files for the purpose, because
everything in them is something the control actually needs. Keep any future
ones in `tests/data/` so this directory stays purely what TouchOSC ships.
